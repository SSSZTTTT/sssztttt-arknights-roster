# ARK RECORD

黒・青を基調にした、アークナイツの育成記録サイトと本人用の入力ツールです。

| 置き場所 | 役割 |
| --- | --- |
| GitHub Pages | 全レアリティの一覧、検索・絞り込み、育成集計、サポート依頼 |
| 現在のシートに紐づくGAS | 既存のWiki取得処理、公開データAPI、依頼受付、Discord通知、履歴記録 |
| 独立したGAS | 本人専用の育成入力画面、Googleのデプロイ権限によるアクセス制限、シート更新 |
| Google Sheets | 年別オペレーターデータ、集計、履歴 |

Cloud Runは使用しません。GASが自動的に利用する標準のGoogle Cloudプロジェクトは必要ですが、Cloud Consoleで別途構築・設定する構成ではありません。

## 初回設定

### 1. 公開用：現在のコンテナバインドGAS

現在のシートから「拡張機能 → Apps Script」を開きます。

1. 既存コードを控えたうえで、古い `doGet` / `doPost` を削除し、`gas/public/Code.gs` に置き換えます。同名の関数を複数残さないでください。
2. `gas/public/Core.gs` と `gas/public/Model.gs` を別のスクリプトファイルとして追加します。
3. Wiki自動取得、メニュー、キャッシュ削除など、他の既存関数は残します。
4. プロジェクト設定の「スクリプト プロパティ」に以下を設定します。

| キー | 値 |
| --- | --- |
| `SPREADSHEET_ID` | 現在の新シートのID |
| `DISCORD_WEBHOOK_URL` | Discordで作り直したWebhook URL |
| `REQUEST_COOLDOWN_SECONDS` | 任意。既定値 `180` |
| `GLOBAL_COOLDOWN_SECONDS` | 任意。既定値 `15` |
| `DAILY_REQUEST_LIMIT` | 任意。既定値 `50` |

Webhook URLはコードやGitHub、公開サイトに入れません。以前共有したWebhookは無効化し、新しいURLをこのプロパティにだけ設定してください。

5. V8ランタイムとタイムゾーン `Asia/Tokyo` を使用します。`gas/public/appsscript.json` は必要スコープの参考です。既存マニフェストを丸ごと置換せず、既存処理で必要なスコープや設定を残してください。
6. 「デプロイ → 新しいデプロイ → ウェブアプリ」で、実行するユーザーを自分、アクセスできるユーザーを全員に設定します。Googleの権限確認を完了し、発行された `/exec` URLを控えます。

公開APIの `?action=roster` で `ok: true` とオペレーター一覧が返れば読み取り設定は完了です。`GET` で通知や育成データ変更は行いません。旧APIとレスポンス形式が異なるため、新しいデプロイを作成すると旧サイトの切替前テストがしやすくなります。

### 2. 入力用：独立したGAS

1. [Apps Script](https://script.google.com/home) で新しいプロジェクトを作成します。
2. `gas/admin` の `Code.gs`・`Core.gs`・`Model.gs` を追加し、HTMLファイル `Index` を作って `Index.html` の内容を貼り付けます。
3. プロジェクト設定からマニフェストの表示を有効にして、`appsscript.json` を同名ファイルに反映します。
4. スクリプト プロパティに `SPREADSHEET_ID` を設定します。入力用GASにWebhookや `OWNER_EMAIL` は不要です。以前登録した `OWNER_EMAIL` は削除して構いません（残っていても参照しません）。
5. ウェブアプリとしてデプロイし、実行するユーザーを自分、アクセスできるユーザーを **自分のみ** に設定します。このアカウントでスマホから `/exec` URLを開いて使います。

利用者の制限はGoogleの「自分のみ」で行い、コード内でメールアドレスの追加照合はしません。入力用のマニフェストにも `webapp.access: MYSELF` を指定しています。既存のデプロイを更新するときも、アクセス設定が「自分のみ」であることを確認してください。入力用コードを公開用GASへ入れたり、入力用を「全員」で公開したりしないでください。

画面生成が失敗した場合は `ADMIN_HTML_LOAD` と表示し、認証エラーと区別します。HTMLファイル名が `Index` になっているか確認してください。詳細はGASの実行ログに出ます。

Googleの認可画面・デプロイ設定はアカウント本人が完了してください。コード変更後は、デプロイ管理から新バージョンへ更新する必要があります。

### 3. GitHub Pages

1. `src/config.js` の `apiUrl` に、手順1で発行された公開用の `/exec` URLを入れます。
2. 以下を実行します（外部パッケージのインストールは不要です）。

```sh
node scripts/build.cjs
node scripts/check.cjs
node --test tests/*.test.cjs
```

3. 生成された `index.html` と `assets` を含めてGitHubに反映します。
4. リポジトリのPages公開元を `main` のルートに設定する構成です。設定済みならそのまま使用します。

`apiUrl` が空の間は未接続の案内を表示します。設定とGASの接続確認が済んでから本番ブランチへ取り込んでください。

## 操作

- 一覧：名前・職業・レアリティ・所持・育成途中で絞り込み。行をタップすると詳細とサポート依頼の確認を表示します。
- 育成入力：所持、昇進、レベル、潜在、S1〜S3、X・Y・Δ・αを編集します。「最終昇進・Lv MAX」「対象スキルをすべてM3」でまとめて入力できます。
- スキルの「対象外」はシートの `-` です。全M3操作では対象外の枠を変更しません。将来の例外はS3を手動で設定できます。
- ★6の潜在は6を超えた記録を保持し、集計では6以上を完凸として扱います。
- 集計は所持済みの★4〜6が対象。総合・★6・★5・★4と職業別を切り替えます。スキル分母は `-` の枠だけ除外し、未入力は含めます。
- Lv MAX表示は★6:昇進2/Lv90、★5:昇進2/Lv80、★4:昇進2/Lv70、★3:昇進1/Lv55、★1〜2:未昇進/Lv30で判定します。★3以下の一覧表示は対応しますが集計には含めません。
- 保存前のデータから変更されていた場合は上書きを拒否します。編集を閉じ、一覧の更新ボタンで取得し直してください。

年別シート名は `2020年` のような形式、見出しは `実装日 / レア / 職業 / オペレーター名 / 昇進 / Lv / 潜在 / S1 / S2 / S3 / X / Y / Δ / α / 所持状態` を使用します。列順は見出しから判定します。名前を識別に使用するため、全年度を通じて同名行が重複している場合はエラーにします。育成入力中の行移動・直接編集・インポート処理の同時実行は避けてください。GASプロジェクト間とシート直接操作をひとつのトランザクションとしてロックすることはできません。

公開画面の集計は取得した年別データから計算します。既存の集計シートのセルや数式は変更しません。公開データは、ページの再読み込みまたは更新ボタンで最新化されます。

## 依頼受付の仕組みと制限

データの取得はGAS Content ServiceのJSONPを使います。公開可能なデータだけを返し、コールバック名を制限しています。育成入力にはJSONPを使いません。

依頼はフォーム形式のPOSTでGASに送り、その後、受付番号を使って送信結果を照会します。ブラウザの `no-cors` 応答だけで成功と判断しません。Discordの成功応答を確認できた場合に限り成功と表示し、履歴へ追加します。結果不明の場合は自動再送せず、履歴やDiscordの確認を促します。

既定では同じブラウザからの依頼と同じオペレーターへの依頼を3分間制限します。ブラウザ識別子はリセット可能なので、これだけで厳密な利用者識別はできません。加えて全体で15秒に1件、1日50件（日本時間）の上限をGAS側に設けます。これは通常の連打対策であり、大量アクセスによるGASの実行上限消費まで防ぐものではありません。GASでは元のプロキシのようなIP単位の制限を前提にしません。

受付番号の結果は最大150件・約1時間保持します。同じ番号の再POSTによる二重通知はその保持期間内で防止します。Discord送信とシート履歴は別サービスなので、通知成功後に履歴のみ失敗する可能性があります。

## ローカルプレビューと開発

```sh
node scripts/demo.cjs
node scripts/serve.cjs
```

公開画面は `http://127.0.0.1:4173/?demo=1`、入力画面は `http://127.0.0.1:4173/?demo=1&screen=admin`。保存はページ内だけで、シート更新やDiscord通知は実行しません。再読み込みすると変更は戻ります。`demo.cjs` はプレビューJSONがない場合だけ架空の育成値を持つサンプルを作ります。`preview-data` はGit管理対象外です。

修正元は `src` と `backend` です。`assets` と `gas` はビルド生成物なので、修正後は `node scripts/build.cjs` を実行します。

自動テストは集計ルール、入力検証、メールアドレスを取得できない環境での入力画面・読み書き、HTML読み込み失敗の表示、競合保存の拒否、変更列だけの保存、通知の成功・失敗、重複受付・クールダウン、JSONP処理をカバーします。GAS・Discord呼出しはモックで、実サービスへ送信しません。Googleによるアクセス制限、GASのリダイレクト通信、実際の通知はデプロイ後に別途確認します。
