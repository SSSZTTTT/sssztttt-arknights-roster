# ARK RECORD

黒・青を基調にした、アークナイツの育成記録サイトと本人用の入力ツールです。

| 置き場所 | 役割 |
| --- | --- |
| GitHub Pages | 全レアリティの一覧、検索・絞り込み、育成集計、サポート依頼 |
| 現在のシートに紐づくGAS | 既存のWiki取得処理、公開データAPI、依頼受付、Discord通知、履歴記録 |
| 独立したGAS | 本人専用の育成入力画面、Googleのデプロイ権限によるアクセス制限、シート更新 |
| Google Sheets | 年別オペレーターデータ、集計、履歴 |

GitHub版の入力画面を `/edit/` に追加しました。白基調のUIはGitHub Pagesで表示し、別の認証付きGASに読み書きを依頼します。既存の本人専用GASはそのまま残せます。

Cloud Runは使用しません。従来のGAS版入力には追加のCloud設定は不要です。新しいGitHub版入力では、Googleログイン用のOAuthクライアントだけGoogle Cloud Consoleで設定します。

## GitHub版入力ツールの初回設定

入力画面: `https://sssztttt.github.io/sssztttt-arknights-roster/edit/`

接続先を設定するまでは「接続準備中」と表示し、Googleログイン・シートアクセスは開始しません。

### A. Googleログインを用意する

1. [Google Cloud Console](https://console.cloud.google.com/) で、ログイン用のプロジェクトを作成または選択します。Cloud Runやデータベースは作りません。既存GASのCloudプロジェクトを切り替える必要もありません。
2. 「Google Auth Platform」のブランディングを設定します。アプリ名は「アークナイツ育成入力」などにします。連絡先には自分のメールアドレスを設定します。
3. 対象は「外部」、テストユーザーには利用する自分のGoogleアカウントを追加します。本人用なのでテスト段階から接続確認できます。
4. データアクセスは `openid` と `https://www.googleapis.com/auth/userinfo.email` の基本的な本人確認用スコープだけを使います。Googleログイン側でシートの権限を要求する必要はありません。
5. クライアントを作成し、種類は「ウェブ アプリケーション」にします。
6. 「承認済みのJavaScript生成元」に `https://sssztttt.github.io` を登録します。
7. 「承認済みのリダイレクトURI」にも `https://sssztttt.github.io` を登録します。今回のGoogleポップアップ方式では、認証コード交換時のURIは `/edit/` ではなくページのオリジンです。
8. クライアントIDとクライアントシークレットを控えます。シークレットはGASのプロパティにだけ入力し、チャット・GitHub・画面のJavaScriptには貼りません。

### B. GitHub入力用のGASを新しく作る

既存の入力用GAS・公開用GASには追加しません。新しい独立GASプロジェクトを作り、以下の専用コードだけを入れます。

1. `gas/editor` の `Model.gs`・`Core.gs`・`Training.gs`・`OperatorImport.gs`・`ImportApi.gs`・`Code.gs` を追加します。全文コピー用の「GitHub入力用_Code.gs.txt」なら6ファイル分を結合してあるので、1つのCode.gsへ全文貼り付けるだけでも動きます。両方の入れ方を同時には行わないでください。
2. `gas/editor/appsscript.json` を反映します。このGASには `Index.html` は不要です。
3. スクリプトプロパティに次を設定します。

| キー | 設定する値 |
| --- | --- |
| `SPREADSHEET_ID` | 現在使用しているスプレッドシートのID |
| `OAUTH_CLIENT_ID` | Aで作成したOAuthクライアントID |
| `OAUTH_CLIENT_SECRET` | Aで作成したクライアントシークレット |
| `OWNER_EMAIL` | ログインを許可する自分のGoogleアカウントのメールアドレス |
| `EDITOR_ORIGIN` | `https://sssztttt.github.io`（末尾のスラッシュやリポジトリ名は付けない） |

4. 新しいウェブアプリとして「実行するユーザー：自分」「アクセスできるユーザー：全員」でデプロイします。新しいAPIは匿名アクセスできるURLでも、Google本人認証に成功しない限り育成データの取得・保存を実行しません。従来の `gas/admin` は引き続き「自分のみ」です。従来コードを「全員」に変更しないでください。
5. 自分のアカウントでGASの必要権限を確認・許可し、末尾 `/exec` のURLを控えます。このURL自体は秘密情報ではありません。

### C. GitHubと接続する

1. Bの新しい `/exec` URLだけを `src/editor-config.js` の `apiUrl` に設定します。公開用APIや従来の入力画面のURLは使いません。
2. `node scripts/build.cjs`、`node scripts/check.cjs`、`node --test tests/*.test.cjs` を実行し、生成物もGitHubへ反映します。
3. `/edit/` を開き、「Googleでログイン」から指定したアカウントでログインします。Safariのポップアップが開かなければ、そのページのポップアップ許可を確認します。
4. 一覧取得、1項目の保存・再取得、ログアウトを確認します。別アカウントでは入力データの取得・保存が拒否されることを確認します。

GASデプロイとGoogleログインの実接続、iPhoneのスクロールは設定後に実機確認が必要です。公開ページのサポート依頼とは別の接続で、Discord通知は行いません。

### Wikiから新規取得

入力画面の右上にある「取得」から実行します。確認画面に新規オペレーターの名前・職業・レアリティ・日本実装日を表示し、「OK・追加する」を押したときだけ書き込みます。基本情報の訂正もある場合は変更前後を表示します。追加対象がなければその旨を表示し、キャンセル時はシートを変更しません。

- 以前のコンテナバインドGASの取得・解析・差分作成・追記ロジックを、独立したGitHub入力用GASに組み込んでいます。元のGASを外部から起動する方式ではありません。シートIDは既存のスクリプトプロパティを使います。
- 未実装・未来日を除外し、名前は1文字でも取得します。既存の育成値・特化例外・モジュール・所持状態は保持します。新規分は未所持で追加し、スキル枠は既存のレアリティ別初期化ルールを使います。
- 確認内容はサーバー側に最大10分保存します。CacheServiceの早期破棄や再取得で無効になった場合は、改めて取得してください。確認内容はログインセッションと設定に紐付け、クライアントから渡された追加内容は採用しません。
- 確認後に年別シートや集計参照式が変更された場合は書き込み前に停止します。新年シート・集計の参照先更新も既存処理を維持しています。
- 書き込み開始前に確認情報を消費し、二重送信・自動再送による重複を防ぎます。途中失敗の場合は一部反映の可能性を表示するので、一覧を更新してから再取得してください。GASの書き込みは一括トランザクションではありません。コンテナバインド側の取得処理と同時に実行しないでください。
- この機能の導入時はGitHub入力用GASのCode.gs全文を更新し、既存デプロイを「新バージョン」で更新します。プロパティ・マニフェスト・URLの変更は不要です。

### ログイン時の待ち時間

初回ログインは、本人確認・セッション発行が完了したGAS応答に一覧データを同梱します。正常時のGAS通信は `prepare → login` の2回で、別途 `read` を待ちません。旧デプロイや一覧同梱失敗時は従来の認証付き `read` へフォールバックします。一覧取得だけが失敗した場合は発行済みセッションを保持して再試行できます。既存セッションでの再訪は従来どおりGASで有効性を確認してから表示します。

Googleログインライブラリと認証準備を並行して開始し、入力画面はデータ準備後の演出用待機（最大約1.1秒）も行いません。公開画面のロード演出は維持します。通信削減の適用にはGitHub入力用GASの既存デプロイを新バージョンへ更新してください。設定値・URL・権限の変更は不要です。

### 認証と保存の動作

- Googleからブラウザに返された一度限りの認証コードを、GASがGoogleのHTTPSトークンエンドポイントへ直接送って確認します。クライアントが自己申告したメールやIDトークンではログインできません。検証するのは発行元・クライアントID・期限・メール確認済み状態・許可メール・GoogleアカウントIDです。
- 認証開始時のstateは5分で失効し、一度だけ使用できます。ブラウザごとのランダム値にも結び付けます。初回に許可メールでログインしたGoogleアカウントIDを `OWNER_GOOGLE_SUB` に自動登録し、以後はそのIDも照合します。
- 入力用セッションは最終利用から30日間・同時5件。一覧取得・保存の認証時にGAS側で期限を30日先へ延長します。ブラウザのlocalStorageに保持するためタブやブラウザを閉じても復元でき、GASにはトークンのSHA-256ハッシュだけを保存します。旧sessionStorageの有効なログインは取得成功時に移行します。保存領域が使えない環境ではメモリにだけ保持し、サイトデータの削除やSafariによる削除後には再ログインが必要です。Googleのアクセストークン・更新トークン・IDトークンは保存しません。
- Googleアカウントからのログアウトと入力ツールのログアウトは連動しません。入力ツールでログアウトするとGAS側のセッションとブラウザの保持情報を削除し、同じブラウザの他タブもログアウトします。Googleのログイン状態をバックグラウンドで監視する方式ではありません。
- すべての取得・保存要求にセッション照合があります。秘密情報をURL・JSONPに入れません。POSTの返答は非表示iframeから、固定のGitHubオリジンへpostMessageで返します。画面はiframeの外で表示し、受信側は返答元オリジン・要求専用iframeの子孫ウィンドウ・ランダムな照合値をすべて確認します。
- `ALLOWALL` はこの通信専用の返答ページだけに使います。返答ページに育成操作UIはなく、他サイトへは返答を送りません。公開API・本人専用GASのアクセス設定は変更しません。
- 保存結果を受け取れなかった場合は、自動再送も成功表示もしません。一覧を更新して実際の保存状態を確認してください。保存前の版照合・入力値検証・変更列だけの保存は従来と共通です。
- ログアウトでそのセッションを失効させます。全端末を失効させるには `SESSION_VERSION` プロパティを別の値に変えてください。許可アカウントを変更する場合は `OWNER_EMAIL` を変更し、`OWNER_GOOGLE_SUB` を削除してから、新しい本人アカウントでログインします。
- ログイン開始は全体で1時間80回まで。これは濫用の軽減策で、GASの実行割当を大量アクセスから完全に守るものではありません。

参考: [Googleのコードモデル](https://developers.google.com/identity/oauth2/web/guides/use-code-model)、[OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)、[GASのiframe設定](https://developers.google.com/apps-script/reference/html/x-frame-options-mode)。

## 初回設定

### 1. 公開用：現在のコンテナバインドGAS

現在のシートから「拡張機能 → Apps Script」を開きます。

1. 既存コードを控えたうえで、古い `doGet` / `doPost` を削除し、`gas/public/Code.gs` に置き換えます。同名の関数を複数残さないでください。
2. `gas/public/Core.gs` と `gas/public/Model.gs` を別のスクリプトファイルとして追加します。
3. Wiki自動取得、メニュー、キャッシュ削除など、他の既存関数は残します。
4. プロジェクト設定の「スクリプト プロパティ」に以下を設定します。

| キー | 値 |
| --- | --- |
| `SPREADSHEET_ID` | 現在の新シートのID |
| `DISCORD_WEBHOOK_URL` | Discordで作り直したWebhook URL |
| `REQUEST_COOLDOWN_SECONDS` | 任意。既定値 `180` |
| `GLOBAL_COOLDOWN_SECONDS` | 任意。既定値 `15` |
| `DAILY_REQUEST_LIMIT` | 任意。既定値 `50` |

Webhook URLはコードやGitHub、公開サイトに入れません。以前共有したWebhookは無効化し、新しいURLをこのプロパティにだけ設定してください。

`SPREADSHEET_ID` も公開用・入力用それぞれのスクリプトプロパティにのみ保存します。未設定時の固定IDへの代替はありません。GASのコードを更新する前に、この設定が入っていることを確認してください。GitHub Pagesはシート自体を「リンクを知っている全員」に共有する必要はありません。

5. V8ランタイムとタイムゾーン `Asia/Tokyo` を使用します。`gas/public/appsscript.json` は必要スコープの参考です。既存マニフェストを丸ごと置換せず、既存処理で必要なスコープや設定を残してください。
6. 「デプロイ → 新しいデプロイ → ウェブアプリ」で、実行するユーザーを自分、アクセスできるユーザーを全員に設定します。Googleの権限確認を完了し、発行された `/exec` URLを控えます。

公開APIの `?action=roster` で `ok: true` とオペレーター一覧が返れば読み取り設定は完了です。`GET` で通知や育成データ変更は行いません。旧APIとレスポンス形式が異なるため、新しいデプロイを作成すると旧サイトの切替前テストがしやすくなります。

### 2. 入力用：独立したGAS

1. [Apps Script](https://script.google.com/home) で新しいプロジェクトを作成します。
2. `gas/admin` の `Code.gs`・`Core.gs`・`Model.gs`・`Training.gs` を追加し、HTMLファイル `Index` を作って `Index.html` の内容を貼り付けます。
3. プロジェクト設定からマニフェストの表示を有効にして、`appsscript.json` を同名ファイルに反映します。
4. スクリプト プロパティに `SPREADSHEET_ID` を設定します。入力用GASにWebhookや `OWNER_EMAIL` は不要です。以前登録した `OWNER_EMAIL` は削除して構いません（残っていても参照しません）。
5. ウェブアプリとしてデプロイし、実行するユーザーを自分、アクセスできるユーザーを **自分のみ** に設定します。このアカウントでスマホから `/exec` URLを開いて使います。

利用者の制限はGoogleの「自分のみ」で行い、コード内でメールアドレスの追加照合はしません。入力用のマニフェストにも `webapp.access: MYSELF` を指定しています。既存のデプロイを更新するときも、アクセス設定が「自分のみ」であることを確認してください。入力用コードを公開用GASへ入れたり、入力用を「全員」で公開したりしないでください。

画面生成が失敗した場合は `ADMIN_HTML_LOAD` と表示し、認証エラーと区別します。HTMLファイル名が `Index` になっているか確認してください。詳細はGASの実行ログに出ます。

Googleの認可画面・デプロイ設定はアカウント本人が完了してください。コード変更後は、デプロイ管理から新バージョンへ更新する必要があります。

### 3. GitHub Pages

1. `src/config.js` の `apiUrl` に、手順1で発行された公開用の `/exec` URLを入れます。
2. 以下を実行します（外部パッケージのインストールは不要です）。

```sh
node scripts/build.cjs
node scripts/check.cjs
node --test tests/*.test.cjs
```

3. 生成された `index.html` と `assets` を含めてGitHubに反映します。
4. リポジトリのPages公開元を `main` のルートに設定する構成です。設定済みならそのまま使用します。

`apiUrl` が空の間は未接続の案内を表示します。設定とGASの接続確認が済んでから本番ブランチへ取り込んでください。

## 操作

- 一覧：名前・職業・レアリティ・所持・育成途中で絞り込み。行をタップすると詳細とサポート依頼の確認を表示します。
- 育成入力：所持、昇進、レベル、潜在、S1〜S3、X・Y・Δ・αを編集します。「最終昇進・Lv MAX」「対象スキルをすべてM3」でまとめて入力できます。
- スキルの「対象外」はシートの `-` です。全M3操作では対象外の枠を変更しません。将来の例外はS3を手動で設定できます。
- ★6の潜在は6を超えた記録を保持し、集計では6以上を完凸として扱います。
- 集計は所持済みの★4〜6が対象。総合・★6・★5・★4と職業別を切り替えます。スキル分母は `-` の枠だけ除外し、未入力は含めます。
- Lv MAX表示は★6:昇進2/Lv90、★5:昇進2/Lv80、★4:昇進2/Lv70、★3:昇進1/Lv55、★1〜2:未昇進/Lv30で判定します。★3以下の一覧表示は対応しますが集計には含めません。
- 保存前のデータから変更されていた場合は上書きを拒否します。編集を閉じ、一覧の更新ボタンで取得し直してください。

年別シート名は `2020年` のような形式、見出しは `実装日 / レア / 職業 / オペレーター名 / 昇進 / Lv / 潜在 / S1 / S2 / S3 / X / Y / Δ / α / 所持状態` を使用します。列順は見出しから判定します。名前を識別に使用するため、全年度を通じて同名行が重複している場合はエラーにします。育成入力中の行移動・直接編集・インポート処理の同時実行は避けてください。GASプロジェクト間とシート直接操作をひとつのトランザクションとしてロックすることはできません。

公開画面の集計は取得した年別データから計算します。既存の集計シートのセルや数式は変更しません。公開データは、ページの再読み込みまたは更新ボタンで最新化されます。

## 依頼受付の仕組みと制限

データの取得はGAS Content ServiceのJSONPを使います。公開可能なデータだけを返し、コールバック名を制限しています。育成入力にはJSONPを使いません。

依頼はフォーム形式のPOSTでGASに送り、その後、受付番号を使って送信結果を照会します。ブラウザの `no-cors` 応答だけで成功と判断しません。Discordの成功応答を確認できた場合に限り成功と表示し、履歴へ追加します。結果不明の場合は自動再送せず、履歴やDiscordの確認を促します。

既定では同じブラウザからの依頼と同じオペレーターへの依頼を3分間制限します。ブラウザ識別子はリセット可能なので、これだけで厳密な利用者識別はできません。加えて全体で15秒に1件、1日50件（日本時間）の上限をGAS側に設けます。これは通常の連打対策であり、大量アクセスによるGASの実行上限消費まで防ぐものではありません。GASでは元のプロキシのようなIP単位の制限を前提にしません。

受付番号の結果は最大150件・約1時間保持します。同じ番号の再POSTによる二重通知はその保持期間内で防止します。Discord送信とシート履歴は別サービスなので、通知成功後に履歴のみ失敗する可能性があります。

## ローカルプレビューと開発

```sh
node scripts/demo.cjs
node scripts/serve.cjs
```

公開画面は `http://127.0.0.1:4173/?demo=1`、入力画面は `http://127.0.0.1:4173/?demo=1&screen=admin`。保存はページ内だけで、シート更新やDiscord通知は実行しません。再読み込みすると変更は戻ります。`demo.cjs` はプレビューJSONがない場合だけ架空の育成値を持つサンプルを作ります。`preview-data` はGit管理対象外です。

修正元は `src` と `backend` です。`assets` と `gas` はビルド生成物なので、修正後は `node scripts/build.cjs` を実行します。

公開前は `node scripts/check.cjs` を実行してください。追跡ファイルと公開・ソース用ディレクトリを検査し、メールアドレス、直接記載したスプレッドシートID、Discord Webhookを検出した場合は値を表示せず停止します。例示用アドレス・GitHubの `noreply` アドレス・テスト内の明示的なダミーWebhookは除外します。公開するコミットの作成者メールには、自分のGitHub設定に表示される `noreply` アドレスを使ってください。現在のファイルやメール設定を変更しても、過去のコミット内容と作成者メールは消えないため、既公開の履歴は別途整理が必要です。

自動テストは集計ルール、入力検証、メールアドレスを取得できない環境での入力画面・読み書き、HTML読み込み失敗の表示、競合保存の拒否、変更列だけの保存、通知の成功・失敗、重複受付・クールダウン、JSONP処理をカバーします。GAS・Discord呼出しはモックで、実サービスへ送信しません。Googleによるアクセス制限、GASのリダイレクト通信、実際の通知はデプロイ後に別途確認します。

参考：[GAS Web Apps](https://developers.google.com/apps-script/guides/web)、[Content Service](https://developers.google.com/apps-script/guides/content)、[Session](https://developers.google.com/apps-script/reference/base/session)、[Discord Webhook](https://docs.discord.com/developers/resources/webhook)。

## 一覧の並び順

公開・入力とも標準は「レベル順」です。昇進段階（2→1→0、未入力は最後）、その段階内のレベル降順、先鋒→前衛→重装→狙撃→術師→医療→補助→特殊、名前の順で比較します。同じ昇進・レベルなら、レアリティや実装日で職業順を上書きしません。

名前は漢字で始まるものを後ろにまとめ、それ以外は日本語の照合順、漢字名同士はピンイン順です。提示された「百錬ガヴィル→赤刃明霄チェン→豊川祥子→怒潮ズィマー→聖約イグゼキュター→司霆レイズ→耀騎士ニアール」との一致をテストしています。ゲーム内部の全仕様との一致を確認したものではありません。実装日順・レアリティ順・名前順も選択できます。
